## 0. TL;DR

- **Web 联机德州扑克**（虚拟、不可兑换筹码），朋友之间开私人房；**不含**充值/提现/真钱/可兑换代币。
- 规格书 §13 的第 0–5 阶段**全部完成**，之后又补做了聊天/房间日志、手牌历史、提示音、全下逐张亮牌、

  SQLite 单文件；**禁止** Redis / MySQL / 独立前端部署 / 微服务 / 生产双进程。

### 1.1 两个环境陷阱

1. **`.npmrc` 的 `cache=./.npm-cache`**：本项目最初所在沙箱不允许写 `~/.npm`，`npm ci` 会 `EPERM`。
   普通机器可删掉该文件；若环境变量 `npm_config_cache` 存在会覆盖 `.npmrc`，此时显式加 `--cache ./.npm-cache`。
2. **PrimeVue 许可证**：`primevue@5.x` / `primeicons@8.x` 已改为 PrimeTek 商业许可，未配 key 时生产界面
   右下角常驻 “Invalid PrimeUI License” 水印（实测截图确认）。依赖**锁定在最后一批 MIT 版本**：
   `primevue@4.5.5` / `@primevue/themes@4.5.4` / `primeicons@7.0.0`。升级 5.x 前必须先确认许可。

## 4. 功能现状（已实现，全部有测试或 e2e 覆盖）

- **大厅**：创建私人房（房名 / **初始筹码** / **买入上限**；**固定 9 人桌，不再让房主选座位数**）、
  邀请链接加入、房间不存在/满员提示、当前开放桌数。
  **房间号是 6 位纯数字**（`ROOM_ID_DIGITS`，首位非 0）：建房时撞号（含已关闭的历史房间）自动重摇，
  大厅也能直接按号加入（见 §6.8）。
- **牌桌里的邀请面板**（抽屉「邀请」分节 + 顶栏/「更多」入口）：把 6 位房间号当桌牌摆出来，
  带只读邀请链接与「复制邀请链接 / 复制房间号」；局域网 http 明文下没有剪贴板 API 时退到
  「已选中，按 Ctrl/⌘ + C 复制」（见 §6.9、§9.33）。
- **座位与买入**：无等候页；邀请链接直接进牌桌（旁观者）→ **点桌面上的空位**（空位自带座位号与「入座」）
  → 确认买入 → 落座。买入区间 = 房主设的「初始筹码（默认 2000）～ 买入上限（默认 5000）」，
  步进 = 小盲，服务端同样收敛；**离座 = 保留座位与筹码**（虚线描边 + 「已离座」），
  **退出房间 = 释放座位**；掉线超宽限期（默认 5 分钟，`SEAT_RELEASE_MS`）自动释放。
- **牌局**：无限注德州，服务端洗牌/发牌/裁定；盲注 10/20（含双人桌例外）、最小加注、未满额 all-in 不重开加注、
  边池与平分、行动倒计时（20s，超时 check/fold）、全下逐张亮牌（翻牌→转牌→河牌，每段 750ms）。
- **网络一致性**：重连快照、命令幂等（`requestId`）、过期版本拒绝、断线重连与时钟偏移校正。
- **聊天**：玩家发言 + 系统房间日志（入座/离座/开局/超时/结算/被移除）、未读数、日期/时间分组、
  未读分隔线、**@ 提醒**（服务端按昵称解析）、消息搜索、同人连续发言折叠。
- **手牌历史**：每房最近 20 手，重启后从 `hand_results` 重载，抽屉内可查。
- **提示音**：Web Audio 现场合成（无音频素材），默认关，顶栏开关，本地持久化。
- **主持人移除玩家**：`room.kick`（含旁观者名单 `room.members`）；被移除者定向收到 `unauthorized`
  → 错误页 + 清本地凭证；座位按「退出房间」同样规则释放。
- **房间生命周期**（第 7 轮需求）：**所有人都退出 → 立即关闭**；**没人落座且房间里也没人** → 关闭；
  **5 分钟没有任何玩家操作**（最后一个人掉线/退出后 5 分钟，或建了房一直没人连）→ 关闭。
  回收器每 60 秒扫一次，关闭时会清掉回合/亮牌/座位释放定时器并删除快照。
  只要还有人在线就绝不回收——正在玩的桌子不受影响。
- **观战**：座位满了仍可进（**观战位上限 = 座位数 × 2**，9 人桌 = 18 个未落座的人，见
  `joinRoom()` 的 `observers >= room.maxSeats * 2`），拿不到任何底牌、无操作区；
  **落座入口只有桌面上的空位**（底部不再有第二套「选择座位」UI），点空位 → 确认买入即落座。
- **多桌上限**：服务器全局最多同时 **10 桌**（`DEFAULT_MAX_ROOMS = 10`，`MAX_ROOMS` 可覆盖）。
- **响应式**：桌面 1440×900 / 1280×720，手机竖屏 390×844 / 360×740。
  **手机版只支持竖屏**（第 1 项需求）：横屏时用整屏遮罩提示「请竖屏使用」，不渲染牌桌；
  竖屏两个规格档「一屏放下」：顶栏 + 提示 + 通知槽 + 牌桌 + 底部区全部可见、页面不出现纵向滚动（见 §6.6）；
  9 人桌零重叠（靠 `npm run probe:table` 量像素确认，验收档已改为竖屏两档）。

## 5. 运行与部署要点

- **生产**：`npm run build` → `npm start`；Fastify 一个进程同时提供 `dist/client` 静态页、HTTP API、WebSocket。

## 6. UI 与交互契约（用户明确要求过的部分，改动前先读这一节）

### 6.1 牌面（`PlayingCard.vue`）

- 只有**左上角**「点数 + 花色」与**右下角镜像**角标；**中间不画大花色**（`.pip` 已删除，e2e 断言其数量为 0）。
- 点数用真实字形：`2–10 / J / Q / K / A`，**10 就是「10」**（不是七段数码管的 T，也不是 `T`）。
- 花色字形与点数同处一个角标（形状 + 颜色双重区分）；颜色不是唯一区分手段。
- 角标字号按牌宽缩放：点数 `0.46 × 牌宽`（10 为 `0.4`）、花色 `0.32 × 牌宽`。
  上限由「左右两个角标不接触」定死，改字号前先看该文件里的推导注释。
- 无障碍：`role="img"` + 中文 `aria-label`（如「黑桃 A」）；背面是「盖住的牌」。
- 尺寸档位：`sm` 26px（座位/结算最佳五张）、`md` 42px（公共牌）、`lg` 58px（本人底牌）。

### 6.2 玩家座位面板（`PlayerSeat.vue`）

- 面板**左侧自左向右 = 座位号 + 牌局角色槽位**：座位号是小小的一枚徽标（第 4 项需求把它从
  「昵称上方单独一行」搬到左侧同行，整块面板因此从两行收到一行、矮 ~13px），
  右侧是 `D`（庄家）/ `SB`（小盲）/ `BB`（大盲）胶囊，双人桌同一座位可能同时挂 `D + SB`。
- **离座的人不画成玩家卡**：别人看到的是桌面上一个小胶囊「N 已离座」（`.away-pill`，一行、
  约 32px）；本人看到的则是可点的「N 坐回」空位卡（点它直接坐回，筹码跟人走）。
- **不画头像框、不画首字头像**（`.avatar` / `.seat-aura` 已整体删除，e2e 断言数量为 0）；
  **没有角色时整块不渲染也不占位**，昵称与筹码直接顶到内边距。
- 角色胶囊是纯视觉（`aria-hidden="true"`），完整说法在座位 `aria-label` 的「庄家位 / 小盲 / 大盲」里。
- 面板其余信息：昵称（+ 本人「你」标签）、筹码、断线图标 / `ALL IN` 标记、本轮下注角标（矮屏与竖屏）。
- **本人座位不画底牌**（底部操作区有更大的同一副牌），桌面端也不画 `YOUR TURN` + 进度条
  （底部操作区有同一套；单挑时本人的下注筹码正好落在那一行）。
- **座位面板高度是小屏的硬通货**：矮屏（`max-height: 430px`）与竖屏（`max-width: 560px` + portrait）
  只保留「角色 + 昵称 + 筹码 + 状态标记」，内边距收到 3px。

### 6.2.1 观战面板（`TableView.vue` 的 `.spectator`）

- 只留：状态（`观战中` / `已离座` + 说明）、`已入座 x/9` 与一句指路。
- **不再有「选择座位」网格**（第 3 项需求）：座位号与「入座」已经画在桌面的每个空位上
  （`PokerTable` 的 `.seat-empty`），两处并存只会让人不知道该点哪个。
  e2e 里把「没有第二套选座 UI」钉住了（`.spectator-seat-picker` / `.seat-picker` 计数为 0）。
- **「退出房间」与「离座」搬到底部操作栏**（第 3 项需求），观战者也会渲染底部栏——
  否则旁观的人没有退出的入口（e2e 断言观战者没有任何动作按钮，但能看到「退出房间」）。

### 6.3 底部「你的底牌」区（`TableView.vue`）

- 左：`你的底牌` 标签 + 两张 `lg` 正向牌；本人不在本手时给「本手没有底牌」占位。
- 右：`当前牌型 <牌型名>` 与 `筹码 <数值>` 一组（`.hero-meta`），再往右是「离座 / 退出房间」。
- **当前牌型 = 本人两张底牌 + 已翻出的公共牌**的最大牌型，**公共牌每翻一段实时更新**：
  翻牌前算 2 张（给「一对 Q / 高牌 A」），翻牌 5 张、转牌 6 张、河牌 7 张。
- 判定来自引擎纯函数 `describeHand()`（`src/engine/evaluate.ts`，只依赖 `src/shared/poker.ts`，
  浏览器可直接 import）；5–7 张走 `evaluateHand()`，**与结算叠层的牌型名同源同说法**。
- 本人底牌为空时（本手已结束/未参与）返回空串并整块不渲染，避免把「公共牌的牌型」显示成「你的牌型」。

### 6.4 底部操作区（`ActionBar.vue`）

- **动作按钮：英文主文本（大号加粗）+ 中文小字辅助**，官方叫法：
  `FOLD 弃牌` / `CHECK 过牌` / `CALL <额> 跟注 <额>` / `BET <额> 下注 <额>` / `RAISE <额> 加注 <额>` / `ALL IN <额> 全下 <额>`。
  `aria-label` **同时包含英文与中文**（只留英文会让中文用户与既有 e2e 选择器找不到按钮）。
- **额度台（`.sizing`）**：一块带底色的控制台，左侧「金额数字输入 + 滑块 + 合法区间 `min–max`」，
  右侧一排**快捷额度**（用户要求「最右侧的按钮多几个」）：
  `1/2 POT 半池` / `2/3 POT 2/3 池` / `POT 满池` / `OVERBET 超池`，按钮上同时给出**实际数值**。
- 快捷额度的语义：`bet` / `raise` 的 `amount` 是**目标总额**，所以按「跟注后的底池」折算
  （`跟注额 + (底池 + 跟注额) × 倍率`）；理想值越界时**禁用而不是悄悄夹到边界**，
  禁用原因写在 `title` 上（挂在未被禁用的外层 `.quick-slot` 上，原生禁用按钮收不到 hover）。
- 换算与夹取只有一套实现：`clampAmount()` / `quickSizes()`（`action-bar-sizing.ts`，有单测）。
- 触控与可达性：快捷按钮 ≥40×48px、相邻间距 ≥8px（UX 规范）、`:focus-visible` 焦点环不被裁、
  `prefers-reduced-motion` 关闭动效、All-in 有二次确认弹窗。
- **局级操作行**（第 3 项需求从顶栏搬下来）：`开始牌局/开始下一手`（主持人，等待或已结算时）、
  `离座`、`退出房间`。离座与退出的图标刻意不同：**离座 = `pi-user-minus`**（人从桌边撤下），
  **退出房间 = `pi-power-off`**（关掉这个房间的连接）——原来两个都是 `pi-sign-out`。
  竖屏下这一行必须一行放得下（三个按钮换行就是 48px，360×740 会被顶出滚动），
  所以竖屏把「开始牌局→开始」「退出房间→退出」缩写并隐藏这两个按钮的图标，
  只给离座留图标；完整说法仍在 `title` 与可访问名称里。
- 竖屏（≤560px 宽）：额度台分两行（金额 + 区间 / 四个档位等宽），区间文案不换行。

### 6.6 竖屏（≤560px 宽）的高度预算 —— 改竖屏版式前必读

390×844 与 360×740 是规格书要求的最小竖屏档，**必须一屏放下**（页面纵向溢出必须为 0）。
`tests/e2e/poker-room.spec.ts` 的「牌桌小屏几何」用例里有这条断言（会截图 `33-portrait-fit-*.png`）。

竖屏的固定占用（390×844 实测）：

| 区块 | 高度 | 竖屏压缩手段 |
|---|---|---|
| 顶栏 `.bar` | 53px | 二级按钮收进「更多」、按钮只留图标（title/aria-label 仍在） |
| 牌桌 `.table` | `min(0.275×dvh, dvh−526px)` | **随视口高度缩放**（844 → 232px，740 → 192px）；526 = 顶栏 53 + 通知槽 26 + 舞台内边距 8 + 最高一档底部区 422 + 余量 |
| 底部区 `.hero` | 约 422px | 底牌 58 → 42px；动作按钮中文小字不显示；额度台压扁（快捷按钮 42px、间距 5px）；隐藏 `YOUR TURN` 倒计时条；局级操作行缩写文案 |
| 通知槽 `.notice-slot` | 固定 26px | 预留高度，通知条出现/消失都不推动牌桌 |

几条不能忘的约束：

- **座位纵向半径 `--seat-anchor-y` 在竖屏是 48%**（桌面默认 45%）：桌面高度改小后，
  9 人桌顶部那排面板会压住中央块；半径是「离桌心多远」，调大才变好（44% 压 5.2px、40% 压 11.3px）。
- **竖屏动作按钮的中文小字只是不显示**（`.act-zh { display: none }`），中文仍在按钮的 `title`
  与 `aria-label` 里，读屏与悬停信息不丢；大屏依旧显示中英双行。
- 触控目标不允许小于 40px：竖屏所有按钮最终仍 ≥40px。
- **产品尺寸范围**：桌面 1440×900 / 1280×720，竖屏 390×844 / 360×740（普通手机大小）；
  手机**横屏不做版式**（844×390 / 740×360 只由 e2e 验「不横向溢出 + 显示『请竖屏使用』遮罩」）。
  **更小的机型不在范围内**（§11）。
- 低于 360×740 的机型无法一屏放下（320×568 溢出约 90px），已在探针里标为「参考档」不计入失败。
- **座位面板内边距在竖屏收窄**（6 → 4px，≤780px 高的机型再收到 3px）：这不是审美选择，
  而是靠它把 9 人桌相邻面板的互压从 5–25px 降到 0（`npm run probe:table` 实测）。

### 6.7 顶部细通知条（`NoticeStrip.vue`）—— 顶栏与牌桌之间

第 6 轮需求：在顶栏与牌桌之间加一条**很细**的区域播报文本事件。

- **位置**：横屏引导之后、`main.stage` 之前（顺序：顶栏 → 横屏引导 → 通知条 → 牌桌 → 底部区）。
  实测落在顶栏下沿与牌桌上沿之间，两边都不压（e2e 断言 `barBottom ≤ stripTop` 且 `stripBottom ≤ tableTop`）。
- **高度**：单行 24–26px，最多同时两条（≈64px），比顶栏（61px）还矮；**没有通知时整块不渲染**，不占一点高度。
  长文本用省略号截断，绝不换行把牌桌顶下去。
- **内容**：服务端每个状态事件带的 `notice`（`session.notice` → `TableView.noticeText`）。
  实测覆盖：`xxx 已重新连接` / `xxx 加入了房间` / `xxx 断线（座位保留至本局结束）` /
  `xxx 掉线超过宽限期，座位已释放` / `xxx 已离座（座位为你保留）` / `xxx 退出了房间` /
  `xxx 已被主持人移出房间` / `第 N 手牌开始` / `第 N 手结算：赢家 +筹码（牌型）` /
  `xxx 超时，系统自动过牌|弃牌`。
- **自动消失**：每条 8 秒后淡出；右侧小 × 可提前收起（24px，只是「提前收起」，不是关键操作）。
- **三条过滤规则**（都是实测踩出来的，改之前先看）：
  1. **历史回放不弹**：进桌/刷新/重连时快照里带的 notice 是历史。判定是「文案与进桌时相同
     **且**版本号未变」——只比文案会把重连后紧接着到达的真实通知一起吞掉（踩过）；
  2. **自己的事不播**：`自己 已重新连接`、`自己 加入了房间`、`自己 买入 N 入座 N 号位` 对自己没有价值
     （桌面已经能看到），别人的同名事件照常播报；
  3. **昵称未知时先挂起 2 秒**：进桌瞬间 `game.mySeat` 还是 null，此时到达的「自己 已重新连接」
     无法与「别人的重新连接」区分；2 秒内自己落座/重连拿到昵称后复查，超时则照常播报（宁可多报不可漏报）。
- **无障碍**：这块**刻意不加 `aria-live`**——牌桌上已有一个 `sr-only` 播报区，两处同时播报会把同一件事念两遍；
  可见文本 + 可聚焦的关闭按钮（`aria-label="关闭通知：…"`）已足够。
- **牌桌中央的浮动提示气泡已删除**：它只显示最后一条且永不清空，与通知条完全重复。

### 6.8 大厅「房间号」（`LobbyView.vue` + `repo.newRoomId()`）

用户要求「房间号纯数字」，契约如下：

- **房间号 = 6 位纯数字、首位非 0**（`ROOM_ID_DIGITS`，`src/shared/poker.ts`）：邀请链接里那串就是它
  （`/table/482913`），能口头念、能短信发。生成用 `randomInt(100000, 1000000)`（无取模偏置）。
- **撞号就重摇**：`newRoomId(isTaken)` 最多试 50 次，`isTaken` 由 `Repo.roomExists()` 给出——
  **已关闭的历史房间也要算占用**（`rooms.room_id` 是主键，重号会让建房写库失败，实测过的坑）。
- 大厅输入框：`inputmode="numeric"`（手机弹数字键盘）+ `:maxlength="ROOM_ID_DIGITS"` + `autocomplete="off"`；
  提交前校验「6 位纯数字」，不合格**当场**提示（`房间号是 6 位数字（例如 482913）…`）并把焦点放回输入框，
  不白跑一趟服务端。
- **升级前建的房间是字母号**（旧的 base64url），只能用当时的邀请链接进；手工按号只认纯数字。
- 建房日志里的「N 人桌」取 `credentials.maxSeats`（房间实际值），**不要用请求里的 `maxSeats`**：
  大厅早就不传这个字段了，直接用会打印成 `undefined 人桌`。

## 7. 服务端日志契约（`src/server/logger.ts` + `log-controller.ts`）

用户要求「精简、通俗」。当前规则：

- **请求级日志全部关闭**：Fastify 默认给每个请求打两行（incoming request / request completed），
  实测光是跑完一轮 e2e（十几个用例、上百次请求）就会刷出上百行，把有用信息淹没。
  关闭方式是 `log-controller.ts` 的 `QuietRequestLogger`（`disableRequestLogging: true`），
  刻意不用已 deprecated 的顶层 `disableRequestLogging`（会打印 FSTDEP023 警告）。
- **只记这几件事**（INFO 级，全部是人话，一行一件事）：
  1. 启动：`数据库已升级到版本 2（本次执行：001_init.sql、002_room_buy_in.sql）`（仅新增迁移时出现）
     + `牌桌服务已就绪：http://host:port（网页 / API / WebSocket 同一端口）｜数据库 …｜Node …`；
  2. 建房：`建房「周五夜局」房主 小满，6 人桌，房间号 T8xdZZmlo78`（房间号＝邀请链接里的那串）；
  3. 每手结算：`周五夜局 第 3 手结算：阿水 +120（两对（A 与 K）），底池 240`（按 handId 去重，
     结算走主流程/逐张亮牌收尾/开下一手补发三条路径也只写一行）；
  4. 房间回收：`已回收 1 个无人在线的房间（超过 30 分钟没人连）`；关服：`收到 SIGINT，正在关闭服务`；
  5. 重启恢复：`已从数据库恢复 1 个未结束的房间`。
- **WARN / ERROR 只在真出问题时出现**：数据库快照损坏被关闭、前端未构建、HTTP/WS 命令处理异常、
  端口监听失败、数据库初始化失败。错误上下文里带 `roomId / playerId / command / method / url / detail`，
  方便定位是哪个房间、哪个请求。
- **格式**：pino 单行 JSON，`base: undefined`（去掉 pid/hostname），ISO 时间戳；
  message 是中文人话，结构化字段另放（grep 用）。`LOG_LEVEL=debug|warn|silent` 可调，
  默认 info；**测试里默认 `silent`**（`NODE_ENV=test` 或 `buildApp({ logLevel: 'silent' })`），
  保证 `node --test` 输出干净。
- **已知的小瑕疵**：Fastify 自己会在监听成功时打一行 `Server listening at …`，与「已就绪」重复。
  Fastify 5 的 `listen()` 不支持按调用传 logger，为一行提示去劫持框架日志不值得，保留。

日志长这样（真实输出，一次建房）：

```

{"level":30,"time":"2026-09-22T05:48:30.646Z","msg":"Server listening at http://127.0.0.1:3399"}
{"level":30,"time":"2026-09-22T05:48:30.647Z","msg":"牌桌服务已就绪：http://127.0.0.1:3399（网页 / API / WebSocket 同一端口）｜数据库 /tmp/logtest.sqlite（版本 2）｜Node v24.18.0"}
```

## 9. 关键设计决策与**已踩过的坑**（改代码前必读）

> 条目**连续编号 1–33**，下面按「服务端 / 客户端 / 测试」分三组；全文的 `§9.NN` 引用都指第 NN 条坑。

### 服务端 / 协议

1. **聊天必须是「轻量事件」**：`chat.message` 不带 `state` / `self`，且**不在** `SERVER_EVENT_TYPES` 里。
   曾经做成状态事件，结果它抢在结算/亮牌事件之前把完整牌面（含 `revealedCards`）发出去，
   导致逐张亮牌序列变成 `0→5→3→4`，并破坏「摊牌前不泄露对手底牌」的时序。**改回去就会重犯。**
2. **版本号必须在写快照之前推进**（`bumpVersion` → `scheduleTurn` → 事务写库 → `publish`），
   否则落库版本比广播版本慢一步，重启恢复后客户端看到版本倒退。
3. **座位占用看 `HoldemTable.isSeatAvailable()`**，不要直接判断 `seatAt()` 是否存在：
   手牌进行中离座的玩家以 `pendingLeave` 保留到本手结束，那个座位对新玩家是空的。
4. **离座 = 保留座位（away），退出 = 释放座位（removePlayer）**：`away` 的座位不参与下一手
   （`inHand=false`、跳过庄位/盲位），但 `isSeatAvailable` 为 false；只有本人 `sit` 才清除 `away`。
   离座/退出的弃牌必须走 `foldOut()`（等价 fold 动作），只在自己是行动者时推进会让本手卡在 preflop。
5. **任何命令都可能结束本手，结算必须统一补发**：`seat.leave` / `room.leave` 会自动弃牌，
   只剩一人时本手立刻结算。结算检测写在 switch **之后**（`handWasRunning && !isHandRunning()`），
   不要只放在 `game.action` 分支里。
6. **被踢/退出的人要等 `finishHand()` 才真正释放座位**（`pendingRemoval` / `pendingKickRemoval` /
   `dropPendingKicks()`）。**`member.seat` 不能提前清**：公共状态是按 `room.members` 渲染座位的，
   提前清掉会让「筹码还在池里」的座位在桌面上凭空消失，别人点下去还会收到 `seat_taken`。
7. **「致命错误」与「普通提示」分开**：`unauthorized` / `room_closed` / `room_not_found` 在
   `net/session.ts` 的 `handleFatalRoomError()` 收敛（先 `closing = true`，再清定时器/会话，最后回调跳错误页）。
   其余错误码进 `useSessionStore().lastError`。**改这里要克制：正常断线重连路径不能受影响。**
8. **引擎快照校验按 `phase` 区分**：`waiting` 阶段牌堆本来就是空的，不能要求「牌数 = 52」。
9. **聊天不落库**（刻意的隐私选择）：重启后聊天清空、手牌历史保留。

### 客户端 / UI

10. **`watch` 的 getter 必须返回原始值，不能返回数组**：返回数组时每次求值都是新数组，
    `Object.is` 永不相等，于是**任何**状态广播（别人加入、断线、重连）都会重跑回调——
    实测「一个人刷新页面，全桌所有人再弹一次结算叠层」。
11. **`chat.message` 之外，任何广播都可能重放副作用**：新增 watch/副作用时先问「它会不会被无关事件触发」。
12. **座位面板高度就是小屏的硬通货**：面板每高 10px，公共牌就少 10px 净空；
    改 `PlayerSeat` 的结构（例如往面板里加一行）前先跑 `npm run probe:table`。
13. **环上座位面板的坐标走 CSS 变量**（`--seat-anchor-x/y`、`--seat-w`）；
    `seatStyle()` 的上限必须是 `calc(100% - (半宽 + 4px))`——少一层括号会退化成 `100% - 半宽 + 4px`。
14. **`.center` 的宽度必须等于「内容里较宽的那一行」**：它曾经是 flex 换行 + `flex-basis: 100%`，
    容器的 max-content 把两行宽度相加（403px），于是块比内容宽 87px、公共牌左对齐、还压住侧边座位面板。
    现在是 `flex-direction: column` 两行结构。**改中央区之前先看 `npm run probe:table` 打印的中心块 x 范围。**
15. **边池明细行会让中央块变宽**（277px）：矮屏与竖屏直接隐藏 `.pots`（总额仍在底池胶囊里，
    明细由 `sr-only` 文本与结算叠层承载）。
16. **小屏的下注额写在座位面板角标上**（`.panel-bet`），不要试图挪桌面中央的浮动筹码——
    竖屏里公共牌与贴边座位面板之间只有约 2px 净空。
17. **不要为了一个确认框引入全局服务**：`main.ts` 没注册 `ConfirmationService`，
    直接 `useConfirm()` 会让牌桌页整页渲染不出来（e2e 症状是等 `.table` 超时、控制台无明显报错）。
    第二次确认就地画在弹窗里。
18. **顶栏「更多」菜单是 ≤1100px 才出现的**：给主持人等角色加入口时必须同时在宽屏顶栏露出来
    （`.bar-secondary` 类），否则宽屏下「功能没有入口」。
19. **动作按钮 = 英文主 + 中文辅**，`aria-label` 必须两种语言都有（e2e 与读屏都依赖它）。
20. **快捷额度不能悄悄夹到边界**：越界就禁用 + `title` 说明原因，否则按钮写「超池」却下了「满池」。
21. **额度台里滑块与输入框要对齐**：旧版滑块单独一行、纵向对不齐；现在两者同处 `.controls` 行，
    `align-items: center`，滑块靠 `min-width: 96px` 保底（改布局时容易把它压成一条线）。
22. **矮屏额度台每多一行 = 牌桌少一行**：≤430px 高时整行压到 44px（隐藏滑块与分组标题）；
    740×360 时牌桌只有 118px 高，任何"顺手加的一行"都会把它压没。

### 测试与工具

23. **`npx playwright test` 不会重新构建**，测的是 `dist/client` 旧产物——必须用 **`npm run e2e`**。
24. **e2e 前必须重置 `data/e2e.sqlite`**（`npm run e2e` 内置 `e2e:reset`）：e2e 建的房间不会关闭，
    每轮都会攒下来，几轮后撞上 `MAX_ROOMS=20`，大厅提示「已满」，之后所有用例卡在建房（表现为 `waitForURL` 超时）。
25. **e2e 服务端共用一个进程（3300）**：整套用例的房间都建在这一个服务端上，所以 `MAX_ROOMS` 放宽到 20；
    「最多 10 桌」的产品上限由 `tests/features.test.ts` 单独覆盖；
    另外**房间会被自动回收**（见 §4），所以 e2e 不再需要靠 `e2e:reset` 才能反复跑。
26. **模态叠层会拦住点击**：结算叠层（`.p-dialog-mask`）出现时，顶栏「退出房间」等按钮点不到。
    e2e 里先 `dismissResult(page)` 再做别的操作（第 4 轮就踩到：退出房间一直重试到 90s 超时）。
27. **平分底池时赢家行是多组**：`.best-five` 每个赢家一组、各 5 张，断言不要写死总数。
28. **断言要按语义而不是写死数字**：例如快捷额度断言「按钮上的值一定落在服务端 `min–max` 内」，
    而不是断言某个具体数值（底池会随牌局变化）。
29. **模拟场景只在开发模式可用**（`import.meta.env.DEV`）：要看 9 人桌 / 断线 / 摊牌等状态，
    必须 `npm run dev` 后开 **http://localhost:5173**（`/table/dev?mock=<场景名>`，场景名见 `MOCK_SCENARIO_NAMES`）；
    生产构建里没有 mock，开发时打开 3000 看到的是 `dist/client` 旧构建。
30. **Playwright 的 Chrome profile 放系统临时目录的固定路径**、Chrome 要按**进程组**回收，
    否则 macOS Dock 会不停冒新图标、renderer 变孤儿；受限环境需 `--no-sandbox`。
31. **改小屏几何必须量数字**：跑 `npm run probe:table`（需先 `npm run dev`），它会报重叠像素与页面溢出。
32. **单测与 e2e 不要并发跑**：`npm test` 里有用真实定时器的用例（行动超时、闲置回收、掉线宽限），
    与 e2e（真实 Chrome + 一个 Node 服务进程）抢资源时会偶发 1 项失败；单独重跑即全绿。
    验收顺序：`lint → typecheck → test → e2e`，一条一条来。
33. **`navigator.clipboard` 只在安全上下文（https / localhost）存在**：朋友之间常用的
    `http://192.168.x.x:3000` 下它是 `undefined`，直接调 `writeText` 会抛错、按钮看起来「点了没反应」。
    所以复制一律走 `components/clipboard.ts` 的 `copyText()`，失败时退到「选中文字 + 提示手按 Ctrl/⌘+C」
    （`copyInvite()`）。**新加复制功能不要绕过这个模块。**

## 11. 已知问题与待办（按优先级）

### 未解决

1. **产品范围只覆盖普通手机尺寸**（用户明确要求）：
   - `npm run probe:table` 的**验收档是 4 档**：1440×900 / 1280×720 / 390×844 / 360×740
     （手机横屏在第 7 轮改成「请竖屏使用」遮罩、不渲染牌桌，所以横屏已从探针里移除，
     `scripts/probe-table-geometry.mjs` 的 `VIEWPORTS` 里只有这 4 档 `inScope: true`）。
   - **横屏两档（844×390 / 740×360）由 e2e 覆盖**：只验「不横向溢出 + 出现竖屏提示」，不量座位几何。
   - 更小的机型（320×568 之类，多为 4.7 吋以下的老机）**不在范围内、不做验收**：
     那一档竖屏放不下一屏（实测溢出约 90px，牌桌只剩 152px 高），9 人桌的座位面板也会互压。
     探针仍会把它跑一遍并打印问题，但标成「参考档」且**不计入退出码**。
2. **9 人桌的取舍**：为消掉左列座位面板互相压住，9 人桌不画座位里的底牌背面；
   本人座位的 `YOUR TURN` + 进度条在桌面端也不画（底部操作区有同一套）。
   信息由面板淡化、状态文本、桌面下注筹码与 `aria-label` 承载。
3. **多人机扩容未做**：内存 + 单文件 SQLite；确需扩容时按规格书**另立架构设计**，不得擅自引入 Redis。
4. **发牌动效只有淡入**：按规格书「CSS/SVG 无法满足才引入 PixiJS」判断，CSS 足够，未引入 PixiJS。
5. **`npm run e2e` 依赖系统 Chrome**；目标机无 Chrome 时用 `npm run check:deploy` 代替线上自检。
6. **6 位数字房间号可以被枚举**（「房间号改纯数字」那一轮的权衡，用户要求纯数字）：90 万种组合、全局最多 10 桌，
   脚本扫号理论上能撞进别人的房间当**旁观者**（拿不到任何底牌，主持人可 `room.kick` 移除）。
   旧的 base64url 房间号（≈64 位随机）没有这个问题。要收紧就二选一：
   ① 加长位数（改 `ROOM_ID_DIGITS` 一处即可，8 位 ≈ 9000 万）；② 给 `POST /api/rooms/:roomId/join`
   加按 IP 限流（建房已有 20 次/10 分钟，加入目前不限流）。**等你决定，尚未做。**

### 可选优化（尚未做，等用户决定）

- **抽屉背景是半透明的（实测 `rgba(6, 10, 14, 0.72)`）**：竖屏下能隐约透出牌桌页面的文字，
  前景（分节内容）与后面的幽灵字会打架。这是全项目既有样式（所有分节都一样），
  邀请面板那一轮没动；要改就把 `.p-drawer` 的背景调到 ≈0.92 或不透明（一处样式，但要重新看四档截图）。
- 竖屏把「当前牌型」并入底牌行的顶部而不是右侧，减少一行高度。
- 快捷额度加键盘快捷键（如 `H` 半池 / `P` 满池），需先确认不会与输入冲突。

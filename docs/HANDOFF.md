| 项 | 事实 |
|---|---|

| npm | 11.16.0，仓库内 `.npmrc` 设了 `cache=./.npm-cache` |
| SQLite | **`node:sqlite` 标准库**，没有 better-sqlite3，也没有独立数据库进程 |
| 测试 | **`node --test` 直接跑 `.ts`**，没有 vitest/jest/tsx |
| 客户端 | Vue 3.5 + vue-router 5 + Pinia 4 + **PrimeVue 4.5.5** + Vite 8 |
| 服务端 | Fastify 5 + `@fastify/static` + `@fastify/websocket` + zod 4 |
| e2e | `@playwright/test` 1.63，**复用系统已装 Chrome**（`channel: 'chrome'`），不下载内核 |
| TS 构建 | 源码用 `.ts` 扩展名导入，靠 `rewriteRelativeImportExtensions` 在产物里改写成 `.js` |

### 1.1 两个环境陷阱

1. **`.npmrc` 的 `cache=./.npm-cache`**：本项目最初的沙箱环境不允许写 `~/.npm`，`npm ci` 会报 `EPERM`。
   普通机器**可以删掉这个文件**（`node_modules` 与缓存目录都已 gitignore）。
   如果环境变量 `npm_config_cache` 被设置，它会覆盖 `.npmrc`，此时要显式加 `--cache ./.npm-cache`。
2. **PrimeVue 许可证**：`primevue@5.x` 与 `primeicons@8.x` 已改为 PrimeTek **商业许可**，未配置 key 时生产界面右下角会常驻
   “Invalid PrimeUI License” 水印（本项目实测截图确认过）。因此依赖**锁定在最后一批 MIT 版本**：
   `primevue@4.5.5` / `@primevue/themes@4.5.4` / `primeicons@7.0.0`。**升级 5.x 前必须先确认许可。**

### 2.2 阶段之外补做的功能

- **聊天 / 房间日志**：玩家发言 + `kind:"system"` 房间事件（入座/离座/开局/超时/结算），未读计数、日期与时间分组、未读分隔线、**@ 提醒**（服务端按真实昵称解析并校验）、**消息搜索**、@ 插入按钮、**同人连续发言分组折叠**。
- **手牌历史**：每房最近 20 手，重启后从 `hand_results` 重新载入，抽屉内查看公共牌/底池/赢家/牌型。
- **提示音**：Web Audio 现场合成（**不引入任何音频素材**），默认关、顶栏开关、状态本地持久化。
- **全下逐张亮牌**：服务端按「翻牌→转牌→河牌」每段 750ms 分段推送，最后才发结算；被抢先开下一手时结算会补发。
- **多桌上限**：服务器全局最多同时开放 **3 桌**（`MAX_ROOMS` 可覆盖）；大厅显示「当前开放 x/3 桌」。
- **观战**：座位满了仍可进入观战（观战位上限 = 座位数），观战者拿不到任何底牌、无合法动作，可**自选空位**入座。
- **顶栏收纳**：≤1100px 把二级操作收进「更多」菜单，≤820px 再隐藏阶段与连接状态文案；1440→600px 顶栏始终单行。
- **小屏紧凑牌桌**：矮屏横屏（740×360 等）与竖屏窄屏各有一套紧凑环形布局，9 人桌的公共牌、底池、座位面板零重叠（见 §4.13–4.20）。
- **落座即买入（第 5 项）**：**等候页已删除**。建房或打开邀请链接后直接落在牌桌，先是旁观者；
  桌面空位是可点按钮，点开买入弹窗（范围 = 10 个大盲 ～ 房主自定义上限，步进 = 小盲）确认后落座；本人座位固定在底部中央，桌面不重复画本人底牌。
- **离座 / 退出（第 6 项）**：手牌中随时可离座（自动弃牌并立刻结算），**座位与筹码保留、只有本人能坐回**；
  只有「退出房间」才释放座位（手牌中退出会等本手结算后再移除）。掉线超过宽限期（默认 5 分钟，`SEAT_RELEASE_MS` 可覆盖）自动释放座位。
  别人在桌面上能看出这种状态：座位面板虚线描边 + 状态文案「已离座」，且不画底牌。
- **牌面重做**：点数用真实字形（10 就是「10」，不再是七段数码管的 T），角标 + 中央花色三重可辨（见 §4.21）。
- **结算不再误弹**：刷新页面不会让全桌重弹结算叠层（见 §4.22）。
- **主持人移除玩家（kick，本轮）**：主持人把某人请出房间（`room.kick`）。座位释放规则与「退出房间」完全一致
  （手牌中先弃牌、等本手结算才真正空出）；被移除者**定向**收到 `unauthorized` 后跳到错误页并清掉本地凭证
  （不会无限重连）；其余人看到 `room.player_left` 与系统聊天「XX 已被主持人移出房间」。
  入口：宽屏顶栏「移除玩家」按钮，≤1100px 收进「更多」菜单里的「移除玩家…」（见 §4.23–4.25）。

## 4. 关键设计决策与**已踩过的坑**（最重要的一节）

1. **聊天必须是「轻量事件」**：`chat.message` 不携带 `state`/`self`，且**不在** `SERVER_EVENT_TYPES` 里。
   曾经把它做成状态事件，结果它抢在结算/亮牌事件之前把完整牌面（含 `revealedCards`）发了出去，
   导致逐张亮牌序列变成 `0→5→3→4`，并破坏「摊牌前不泄露对手底牌」的时序。**改回去就会重犯。**
2. **版本号必须在写快照之前推进**（`bumpVersion` → `scheduleTurn` → 事务写库 → `publish`）。
   否则落库版本比广播版本慢一步，重启恢复后客户端看到版本倒退。
3. **`npx playwright test` 不会重新构建**，测的是 `dist/client` 旧产物。
   必须用 **`npm run e2e`**（内部先 `npm run build`）。这一条踩过一次，浪费了一轮排查。
4. **e2e 服务器把 `MAX_ROOMS` 放宽到 20**：整套用例共用一个服务端，多用例各自建房会撞上「最多 3 桌」的产品上限。
   上限本身由 `tests/features.test.ts` 覆盖。
5. **模拟场景（`dev/mock.ts`）只在开发模式可用**（`import.meta.env.DEV`）。要测 9 人桌/断线/摊牌等模拟态，
   必须 `npm run dev` 后开 **http://localhost:5173**；生产构建里没有 mock。
6. **开发与生产的进程模型不同**：`npm run dev` = Vite(5173) + Fastify(3000) 两个进程；生产 = 单进程 3000。
   开发时若打开 3000 看到的是 `dist/client` 旧构建，不会热更新。
7. **Playwright 的 Chrome profile 放在系统临时目录的固定路径**（`<tmp>/poker-e2e-chrome-profile`）。
   曾经每次运行新建 `--user-data-dir`，macOS 会把它当成全新实例，Dock 里不停冒新图标；
   同时 Chrome 要 `detached: true` 启动、按**进程组**回收，否则 renderer/crashpad 会变孤儿进程。
   受限环境里 Chrome 自身沙箱无法初始化（会 SIGTRAP 退出），所以带 `--no-sandbox`。
8. **座位占用看 `HoldemTable.isSeatAvailable()`**，不要直接判断 `seatAt()` 是否存在：
   手牌进行中离座的玩家会以 `pendingLeave` 保留到本手结束（筹码还在池里、牌已弃），
   那个座位对新玩家来说是空的，否则会出现「看起来空着却坐不进去」。
9. **引擎快照校验按 `phase` 区分**：`waiting` 阶段牌堆本来就是空的，不能要求「牌数 = 52」，
   否则从未开过手的等待房间重启时会被误判为损坏快照并关闭（已修，有测试）。
10. **聊天不落库**（刻意选择：不记录聊天内容）。重启后聊天清空、手牌历史保留。
    若要改成都持久化，需要单独设计保留策略与隐私说明。
11. **`src/server/app.ts` 启动时先 `restoreRooms()`**（不再有 `closeStaleRooms`）：
    快照缺失/损坏的房间会被**安全关闭**，日志里报 `restored` / `discarded` 计数。
12. **不要动用户在 3000 端口自己起的服务**：测试请用独立端口 + 独立 `DATABASE_PATH`
    （`playwright.config.ts` 用 3300 / `data/e2e.sqlite`；演练脚本用 3200/3400）。
13. **e2e 每次运行前必须重置 `data/e2e.sqlite`**（`npm run e2e` 已内置 `e2e:reset`）：
    服务端启动会从快照恢复未关闭的房间，而 e2e 建的房间不会在用例结束时关闭，
    于是每跑一轮就多攒几个房间，几轮后撞上 `MAX_ROOMS=20`，大厅直接「已满」，
    之后所有用例都卡在建房那一步（**症状是 waitForURL(/room/) 超时，不是测试代码坏了**）。
14. **聊天分组（同人连续发言折叠）的判定必须保守**：日期分隔、时间分隔（>5 分钟）、
    未读分隔线、系统消息、**任何 @ 提醒**、搜索过滤都会打断分组。
    @ 提醒按「消息里有没有 mention」断开而不是「有没有提到我」——否则同一条消息
    在发送方和接收方会落进不同的分组（实测踩过：发送方把它并进上一条，被 @ 的人在
    自己那边却看到独立一条，两边版式不一致）。
15. **座位面板高度就是小屏的硬通货**：面板每高 10px，公共牌就少 10px 净空。
    矮屏（`max-height: 430px`）与竖屏（`max-width: 560px` + portrait）都只保留
    「昵称 + 筹码 + 状态标记（ALL IN / 断线）」，面板内边距收到 3px（41px 高）；
    上一手动作文字、座位里的小底牌让位；**本人座位的 `YOUR TURN` + 进度条在桌面端也不画**
    （底部操作区有同一套，且单挑时本人的下注筹码正好落在那一行上）。
    **状态文本没有丢**：每个座位的 `aria-label` 里一直带着
    「已弃牌 / 全下 / 已断线 / 正在行动 / 本轮下注 N」（见 `PlayerSeat` 的 `spoken`）。
    9 人桌连底牌背面一起省（`.is-full-ring`），否则左列三个面板必然互压 15px。
16. **环上座位面板的坐标走 CSS 变量**（`--seat-anchor-x/y`、`--seat-w`、`--seat-w` 还参与
    `seatStyle()` 的左右收边 clamp）。所以「贴边座位收窄」可以直接用类名改 `--seat-w`
    （`.is-side-seat`），不用动 JS 布局。注意 `seatStyle()` 的上限必须是
    `calc(100% - (半宽 + 4px))`——少一层括号会退化成 `100% - 半宽 + 4px`，最外侧座位多出 4px。
17. **边池明细行会让中央块横向变宽**：`.pots` 跟底池同行时那一行约 277px，
    加上公共牌就比两侧座位之间的净宽还宽（740×360 实测压住座位面板 17px）。
    矮屏与竖屏直接隐藏 `.pots`：底池总额仍在底池胶囊里，明细由同一处的 `sr-only`
    文本读给屏幕阅读器，结算叠层与手牌历史照常列出每个边池。
18. **改小屏几何必须量数字，不要靠肉眼**：跑 `npm run probe:table`（需先 `npm run dev`，
    见 `scripts/probe-table-geometry.mjs`），它输出**桌面本地坐标**下座位/底池/边池/公共牌
    的重叠像素、中心块坐标与页面溢出量，退出码非 0 表示有重叠。肉眼看截图会漏掉 5–15px 的压边。
19. **`.center` 的宽度必须等于「内容里较宽的那一行」**：它最初是 grid 堆叠（没问题），
    改成 flex 换行并给公共牌 `flex-basis: 100%` 之后，容器的 max-content 会把两行的宽度
    **相加**（79 + 316 = 403），于是块比内容宽 87px、公共牌在块内左对齐、底池看似居中却偏左，
    并且压住侧边座位面板（e2e 报 `座位2 压住中央区 11×42px`）。
    现在的结构是 `[.center-pot（底池+边池）]` + `[公共牌]` 两行 + `flex-direction: column`，
    宽度自然收紧（见该处注释）。**改中央区之前先看 `npm run probe:table` 打印的中心块 x 范围。**
20. **小屏的下注额写在座位面板上，不要试图挪浮动筹码**：竖屏里公共牌宽度与贴边座位面板内沿
    基本贴合（净空约 2px），浮动筹码无论放哪都会压住东西——压自己的筹码数字（15×16px）
    或压最外侧那张牌。现在的做法是矮屏/竖屏不画 `.bet`，改用 `PlayerSeat` 的
    `.panel-bet` 角标（面板右下角，绝对定位，不占布局），明细同步进 `aria-label`。
    桌面端的浮动筹码纵向半径也从 28.7% 收到 25%：单挑时本人筹码原本会压住自己的 YOUR TURN。

21. **删除等候页后的三处连带改动**（第 5 项）：①`joinRoom`/`createRoom` 都不再自动入座，
    否则邀请链接进来就直接坐上去了；②邀请链接从 `/room/:id` 改成 `/table/:id`，
    牌桌在「没有本地凭证」时渲染填昵称的加入面板（`!room.hasCredentials && !game.state`，
    用 `game.state` 兜住开发期模拟场景）；③`room.ready` 已无人发送，字段保留但客户端不再用。
22. **任何命令都可能结束本手，结算必须统一补发**：`seat.leave` / `room.leave` 会自动弃牌，
    只剩一人时本手立刻结算。结算检测原来只写在 `game.action` 分支里，导致「离座把别人打成最后一人」
    时客户端永远收不到 `hand.settled`、手牌也不落库（已改为在 switch 之后统一检测：
    `handWasRunning && !isHandRunning()` → 补 `hand.settled` + 亮牌分段 + 结算文案）。
23. **离座 = 保留座位（away），退出 = 释放座位（removePlayer）**：
    引擎里 `away` 的座位不参与下一手（`inHand=false`、跳过庄位/盲位），但 `isSeatAvailable` 为 false，
    别人坐不进来；只有本人 `sit` 回自己的座位才清除 `away`（筹码照旧，0 筹码时按新买入补充）。
    `removePlayer` 时若筹码还在池里（本手进行中）只能挂 `pendingRemoval`，等 `finishHand()` 再移除。
    离座/退出的弃牌必须走 `foldOut()`（等价 fold 动作：从 `needsToAct` 移除 + `progress()`），
    只在自己是行动者时推进会让本手卡在 preflop（实测踩过）。
25. **「离座」必须在桌面上可见**：保留座位如果看起来和普通在座玩家一样，别人会以为这个座位还能坐。
    `PlayerSeat` 的 `statusText` 把 `seat.away` 放在最前面（优先于弃牌/全下）→ 显示「已离座」，
    面板同时加 `.is-away` 虚线描边；底牌本来就不画（`holeCardCount` 按 `inHand && !away` 算）。
26. **掉线宽限期是「释放座位」而不是「关房间」**：`attach/detach` 各挂一次定时器
    （`seatReleaseMs`，默认 5 分钟，`SEAT_RELEASE_MS` 或 `buildApp({ seatReleaseMs })` 可覆盖），
    超时后 `removePlayer` + `member.seat = null`，成员身份保留为旁观，回来可重新买入入座。
    测试里用 200ms 的值验证，别忘了 `timer.unref()`（否则测试进程不退出）。
27. **公共状态里的座位是按 `room.members` 渲染的**（`publicState()` 只遍历成员）：
    手牌中移除玩家时，`removePlayer()` 会把座位挂 `pendingRemoval` 等结算，但如果这时就把成员
    从 `room.members` 删掉，那个座位在桌面上会**凭空消失**——筹码还在池里却看不见，别人还会
    以为能坐（点下去收到 `seat_taken`）。所以被踢的成员用 `pendingKickRemoval` 标记留到
    `finishHand()` 之后（`dropPendingKicks()`）才真正删除，`member.seat` **不要动**（它是渲染依据）。
28. **「致命错误」必须与「普通提示」分开**：`unauthorized` / `room_closed` / `room_not_found` 说明
    当前身份在这个房间里已经没有意义，继续留着只会按重连退避无限撞墙。收敛点在 `net/session.ts`
    的 `handleFatalRoomError()`：先 `closing = true`（否则服务端随后关连接会触发重连），
    清定时器/本地会话，再回调牌桌页跳错误页（`session.ts` 不认识 vue-router，回调由组件注册）。
    其余错误码照旧进 `useSessionStore().lastError`。**改这里要克制：正常断线重连路径不能受影响。**
29. **PrimeVue 的 `ConfirmDialog` 需要全局 `ConfirmationService`**，而 `main.ts` 没有注册它；
    直接 `useConfirm()` 会让整个牌桌页渲染不出来（e2e 的症状是 `wait for locator('.table')` 超时，
    控制台里没有明显报错）。第二次确认要就地画在弹窗里（`kickTarget` + 行内「确认移除」），
    不要为了一个确认框去改全局 provider。
30. **顶栏的「更多」菜单是 ≤1100px 才出现的**（`.bar-more { display: none }` + 媒体查询）。
    给主持人加的入口必须同时在宽屏顶栏露出来（`.bar-secondary` 类，会在 ≤1100px 自动收起），
    否则 1440px 下功能「没有入口」。e2e 里两档都要覆盖。

| 现象 | 先看这里 |
